Privacy Nested Screen Implementation Plan

When the user taps:

Settings → Privacy

open a dedicated:

PrivacyPage

The purpose should be very clear:

Let the user understand what EH Home collects, why it is used, what is stored locally or remotely, and what they can control.

This screen should be transparent, calm, and simple. Privacy should never feel like a legal maze.

1. Navigation
Settings
   ↓
Privacy
   ↓
PrivacyPage

Back:

PrivacyPage → Settings

Keep Settings selected in the bottom navigation.

2. Header

Use the same nested-screen design:

←   Privacy                              ?

Subtitle:

Manage your data and privacy preferences.

Keep the header compact.

3. Privacy Status Card

At the top, give the user an immediate summary.

Example
┌─────────────────────────────────────┐
│              🛡                     │
│                                     │
│       Your privacy is in your      │
│       control                       │
│                                     │
│       Review what EH Home       │
│       stores and shares.            │
└─────────────────────────────────────┘

Do not display claims such as:

Your data is completely private

unless your actual architecture guarantees that statement.

Use neutral, verifiable wording.

14. Diagnostic Data Sharing

This is especially relevant to your IoT support architecture.

Show:

Diagnostic data


Help Haven understand device and
connection problems.


When enabled, support may receive
technical information such as:


• Device model
• Firmware version
• Connection state
• Recent error information


It does not include:
• Wi-Fi passwords
• Security keys
• Account passwords

The second list must match your actual implementation.

15. Before Support Upload

Review information before sending.


Included:

✓ Connection state
✓ Recent errors


Not included:
✓ Wi-Fi password
✓ Security credentials


[ Review ]
[ Continue ]

This provides a strong privacy boundary.

26. Privacy Repository

Create a dedicated:

PrivacyRepository

Potential interface:

PrivacyRepository
├── getPrivacySummary()
├── getDataCategories()
├── getPermissions()
├── getPrivacyPreferences()
├── updatePrivacyPreferences()
├── requestDataExport()
└── deleteSupportedData()

Every mutation should return:

success
unsupported
unauthorized
unavailable
failed
27. Privacy Data Model
PrivacySummary
├── dataCategories[]
├── permissions[]
├── preferences[]
├── storageLocations[]
└── retentionPolicies[]

Permission:

PrivacyPermission
├── type
├── status
├── purpose
└── systemSettingsAvailable

Preference:

PrivacyPreference
├── id
├── enabled
├── supported
└── description

This allows the UI to remain truthful.

28. Privacy Page Should Not Own Device State

For example:

Device health

belongs to:

DeviceHealthRepository

Privacy only explains:

what data exists
how it is used
what permissions exist
what controls exist

Don't duplicate technical device logic here.

31. Offline Behavior

32. No Fake Controls

This is especially important for privacy.

Don't create:

Analytics
[ OFF ]

if switching it has no real effect.

Don't create:

Delete my data

if the backend doesn't actually delete the data.

A production privacy screen must be more trustworthy than the rest of the app, not less.

34. Important Production Rule

Your privacy architecture should follow the same principle used everywhere else in EH Home:

UI
 ↓
Repository
 ↓
Actual supported behavior

Never:

UI switch
 ↓
local boolean
 ↓
"Privacy setting saved"

without actual enforcement.

For example:

Diagnostic sharing
      ↓
User changes OFF
      ↓
Repository
      ↓
Backend/app configuration
      ↓
Actual diagnostic collection changes
      ↓
Confirmed UI

Final production principle

The Privacy screen should answer four questions immediately:

What data does EH Home have?

Why does it need that data?

Where is the data handled?

What can I control?

That is the correct production direction for EH Home. It also fits cleanly with the architecture you've already established for Rooms, Routines, Activity, Device Health, Home Connection, and Settings.
